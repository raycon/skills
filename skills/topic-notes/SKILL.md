# 주제 노트

있었던 일과 그때의 생각은 일일 기록에 시간순으로 남는다. 그중 사용자가 나중에 다시 찾을 사실과 생각은 주제마다 하나씩 있는 주제 노트에 모아 최신으로 유지한다. 이 스킬은 주제 노트를 다룬다.

가격 하나를 찾으려고 지난 날짜를 다시 읽는 사람은 없다. 그래서 다시 찾을 것은 일일 기록에만 두지 않고 주제 노트로 모은다. 언제 모을지(들어올 때, 회고 때)는 Vault 지침이 정한다.

## Vault 규칙부터 확인한다

Vault의 프로젝트 지침(`CLAUDE.md`, `AGENTS.md` 등)과 기존 주제 노트 몇 개를 읽고, 아래 기본값보다 그것을 따른다.

| 항목 | 기본값 |
| --- | --- |
| 주제 노트 | 일일노트와 원본 보관소 밖, Vault의 폴더(PARA 등)에 있는 노트 |
| frontmatter | `created: "YYYY-MM-DD"`와 `tags`. Vault의 기존 형식을 따른다 |
| 웹 출처 | 노트 끝의 `## 참고` 섹션에 URL을 남긴다 |
| 변경 기록 | 노트 맨 끝의 `## 변경 기록` 섹션에 `` - `YYYY-MM-DD` 항목: 이전 값 → 새 값 ``을 더한다 |

## 사실과 생각

주제 노트에 담는 것은 두 가지이고, 다루는 법이 다르다.

- **사실**(fact): 누가 확인해도 같은 것이다. 가격, 사이즈표, 조건, 방법 같은 것이다. 요약하고 다시 써도 된다. 다시 찾기 어렵거나 결정에 쓰였을 때 기록하고, 검색하면 금방 다시 나오는 것은 기록하지 않는다
- **생각**(thought): 사용자 자신의 것이다. 결론, 취향, 결정과 그 이유, 교훈 같은 것이다("L이 딱 맞음", "다음엔 생수 챙기기"). 한 줄이라도 기록하고, 사용자의 말 그대로 쓴다. 다른 누구도 채울 수 없고, 말을 바꾸면 사용자가 내린 결론이 달라진다
- 생각은 사용자가 말한 것만 기록한다. 결론 없이 느낌만 있으면("개운했다") 일일 기록에만 둔다

가장 쓸모 있는 항목은 둘이 짝을 이룬 것이다. 사이즈표와 실제로 맞았던 사이즈, 가격 세 개와 그중 고른 것 같은 짝은 나란히 둔다.

## 노트를 찾거나 만든다

1. **먼저 찾는다.** 파일 이름, 별칭, 제목, 본문 순으로 찾는다. 좁은 새 노트를 만드는 것보다 넓은 기존 노트에 더하는 편이 낫다. 사실 하나짜리 노트만 잔뜩 있는 Vault는 노트가 없는 것만큼 쓰기 어렵다.
2. **맞는 노트가 없을 때만 만든다.** 이름은 사용자가 검색할 주제로 짓는다. `무선 이어폰`은 되고, `이어폰 가격 비교 11월`은 안 된다. 위치는 Vault의 분류를 따른다. PARA라면 마감이나 끝이 있으면 Project, 계속 이어지면 Area, 참고용이면 Resource다. 애매하면 inbox에 두고 알린다.
3. **사람은 주제가 아니다.** 사람에 대해 알게 된 것은 여기가 아니라 그 사람의 노트에 속한다.

## 항목을 쓴다

- 본문 항목에는 날짜를 붙이지 않는다. 본문은 지금 맞는 값을 보여 준다
- 항목은 속한 제목 아래에 둔다. 노트가 커져 여러 부분으로 나뉘면 제목을 더한다
- 값이나 생각이 바뀌면 본문은 새 값으로 고치고, 이전 값은 변경 기록에 남긴다. 이전 값도 그때는 맞았고, 사용자가 비교하는 대상이 이전 가격인 경우가 많다. 바뀐 생각은 이전 말을 그대로 변경 기록에 옮긴다
- 변경 기록의 날짜는 바뀐 것을 알게 된 날이다. 일일 기록, 녹음, 영수증에서 왔으면 오늘이 아니라 그 일이 있었던 날이다. 새 항목을 더한 것은 기록하지 않는다
- 사용자가 아닌 곳에서 왔으면 출처를 밝힌다. URL은 `## 참고`에, 들은 것은 누가 말했는지 쓴다(`매장 직원`, `[[김민수]]`)

## 노트를 정리한다

주제 노트는 에이전트가 정돈해 둔다. 항목 순서를 바꾸고, 제목 아래로 묶고, 중복을 합치고, 맨 위에 짧은 요약을 둔다. 사실을 적은 항목은 마음껏 다시 쓰고, 생각은 말을 바꾸지 않고 옮긴다. 항목은 하나도 지우지 않고, 변경 기록은 고치지 않는다. 정리는 모양을 바꾸지 기록을 바꾸지 않는다.

여러 노트에 걸친 변경(두 노트 합치기, 노트 옮기기, 이름 바꾸기)은 다른 곳의 링크에 영향을 준다. 계획을 먼저 보여 주고 사용자의 확인을 받는다.

## 노트에서 답한다

질문을 받으면 주제 노트를 먼저 찾고, 답에 쓴 노트를 링크한다. 아직 주제 노트로 옮기지 않은 것은 일일 기록에만 있을 수 있으니, 주제 노트에 없으면 일일 기록도 찾는다. 사용자가 무엇을 정하려 할 때는 관련 사실과 함께 사용자가 예전에 남긴 생각도 보여 준다. 노트는 판단을 대신하지 않고, 사용자가 더 잘 판단하도록 돕는다. 답하려고 다른 곳에서 찾아본 것이 있으면 Vault 지침이 정한 곳에, 없으면 맞는 주제 노트에 기록하고 어디에 넣었는지 알린다.

## Vault를 점검한다

점검을 요청받으면 다음을 찾아 목록으로 보고한다.

- 깨진 링크: 대상이 없는 `[[...]]`
- frontmatter가 없거나, 쿼리가 쓰는 `created` 날짜가 없는 노트
- 빈 노트, inbox에 2주 넘게 남은 노트
- 한 달 동안 고친 적도 없고, 노트 안에도 그 노트를 링크한 곳에도 열린 작업이 없는 Project: 끝났는지, 멈췄는지
- 같은 주제라서 합칠 만한 주제 노트

항목마다 고칠 방법을 제안하고, 사용자가 승인한 것만 고친다.

## 답

어느 주제 노트가 바뀌었는지, 새 노트인지, 무엇을 넣었는지 알린다. 새 노트는 이름을 분명히 말해서, 사용자가 모르는 사이에 Vault가 늘지 않게 한다.
